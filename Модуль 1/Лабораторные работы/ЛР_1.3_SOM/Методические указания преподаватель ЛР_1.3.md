# МЕТОДИЧЕСКИЕ УКАЗАНИЯ ДЛЯ ПРЕПОДАВАТЕЛЯ (ЛР 1.3)

## 1. Цель проверки

Убедиться, что студент:

1. Понимает принципы работы самоорганизующихся карт Кохонена (SOM): алгоритм поиска нейрона-победителя, функцию соседства, процесс обновления весов, топологическое свойство.
2. Способен реализовать все компоненты SOM с использованием только библиотеки NumPy без использования готовых реализаций.
3. Умеет проводить эксперименты с различными параметрами SOM (размер сетки, скорость обучения, радиус соседства) и анализировать их влияние на качество визуализации.
4. Способен интерпретировать результаты визуализации: карту признаков, U-Matrix, Hit Map, компонентные плоскости.
5. Может делать обоснованные выводы о структуре многомерных данных на основе визуализации SOM.

## 2. Как проверять

### 2.1. Проверка кода

Основное внимание – на корректность реализации ключевых компонентов SOM:

- **Инициализация весов (`_initialize_weights`)**:
  - Проверить, что веса инициализируются случайными выборками из данных (а не случайными числами).
  - Размерность весов должна соответствовать (m, n, dim).
  - Использование `np.random.choice` для выбора образцов.

- **Поиск нейрона-победителя (`_find_bmu`)**:
  - Проверить корректность вычисления расстояний (евклидова метрика).
  - Убедиться, что веса правильно преобразуются в плоский массив.
  - Использование `np.argmin` для поиска индекса минимума.
  - Правильное преобразование индекса в координаты (i, j) на сетке.
  - **Дополнительно**: если реализована косинусная метрика, проверить корректность нормализации векторов.

- **Вычисление коэффициентов соседства (`_get_neighborhood`)**:
  - Проверить использование гауссова окна.
  - Корректное вычисление квадрата расстояния от каждого нейрона до BMU.
  - Использование `np.exp` для вычисления коэффициентов.
  - Правильная размерность выходной матрицы (m, n).

- **Алгоритм обучения (`fit`)**:
  - Проверить наличие экспоненциального затухания для lr и sigma.
  - Перемешивание данных на каждой эпохе (`np.random.permutation`).
  - Корректное обновление весов с использованием broadcasting.
  - Вычисление ошибки квантования на каждой эпохе.
  - Сохранение истории ошибок (`train_errors`, `test_errors`).
  - Вывод прогресса обучения.

- **Вычисление ошибки квантования (`_compute_quantization_error`)**:
  - Проверить использование `_find_bmu` для каждого образца.
  - Корректное вычисление среднего расстояния.

- **Предсказание координат BMU (`predict`)**:
  - Проверить возврат координат (i, j) для каждого образца.
  - Возврат расстояний до BMU (опционально, но желательно).

### 2.2. Проверка визуализаций

Студент должен реализовать следующие типы визуализаций:

- **Карта SOM с цветовым кодированием**:
  - Использование цветов: красный, синий, зелёный для трёх классов.
  - Добавление небольшого шума для улучшения визуализации.
  - Размер точек должен отражать ошибку квантования.
  - Наличие легенды, подписей осей и заголовка.
  - Отдельные графики для обучающей и тестовой выборок.

- **U-Matrix (карта расстояний)**:
  - Вычисление средних расстояний между соседними нейронами.
  - Использование 4-связности для определения соседей.
  - Построение тепловой карты с цветовой картой `hot_r` или `viridis`.
  - Нормализация значений для лучшей визуализации.

- **Hit Map (карта попаданий)**:
  - Подсчёт количества попаданий данных в каждый нейрон.
  - Нормализация плотности.
  - Выделение центров кластеров (звёздочками).
  - Добавление легенды с названиями классов.

- **Компонентные плоскости**:
  - Визуализация весов каждого признака (13 плоскостей для Wine).
  - Нормализация каждой плоскости.
  - Организация плоскостей в сетку с подписями признаков.
  - Добавление цветовых шкал.

- **Кривая обучения**:
  - График ошибки квантования по эпохам.
  - Отображение ошибок на обучающей и тестовой выборках.
  - Наличие легенды и подписей осей.

### 2.3. Проверка экспериментов

- **Эксперименты с параметрами**:
  - Проверить проведение экспериментов с различными размерами сетки (5×5, 10×10, 15×15, 20×20).
  - Исследование влияния начальной скорости обучения (lr = 0.1, 0.5, 1.0).
  - Исследование влияния начального радиуса соседства (sigma = 1.0, 3.0, 5.0).
  - Эксперименты с различным количеством эпох (100, 300, 500).
  - **Дополнительно**: сравнение евклидовой и косинусной метрик.

- **Анализ результатов**:
  - Интерпретация карты SOM: насколько чётко разделяются три класса.
  - Анализ U-Matrix: выявление границ между кластерами.
  - Интерпретация Hit Map: определение плотности распределения и центров кластеров.
  - Анализ компонентных плоскостей: определение наиболее важных признаков.
  - Выводы о топологическом свойстве SOM.

### 2.4. Проверка отчёта

Отчёт должен содержать:

1. **Описание метода SOM**:
   - Теоретическое описание алгоритма.
   - Объяснение принципов обучения (поиск BMU, обновление весов, функция соседства).
   - Описание реализованных метрик расстояния.

2. **Описание экспериментов**:
   - Описание датасета Wine (размерность, количество классов).
   - Архитектура SOM (размер сетки, параметры обучения).
   - Способ разделения данных (80/20).

3. **Результаты экспериментов**:
   - Все требуемые графики с подписями и легендами.
   - Таблицы с результатами экспериментов.
   - Сравнение различных конфигураций SOM.

4. **Анализ и выводы**:
   - Интерпретация всех типов визуализаций.
   - Выводы о влиянии параметров на качество визуализации.
   - Рекомендации по выбору параметров SOM.

- Как интерпретировать компонентные плоскости? Как определить важные признаки?
- Почему SOM сохраняет топологию данных? В чём это проявляется?
- Как влияет размер сетки на качество визуализации?
- В чём отличие евклидовой и косинусной метрик в контексте SOM?
